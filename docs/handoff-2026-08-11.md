  records how it left, and it is the only entry ever to do so.
* **The three bugs in `docs/upstream-bugs.md` are bookkeeping, not a task.** They are
  neither to be filed with upstream nor patched locally. Engaging upstream's issue
  tracker is out of scope for this fork (decided 2026-08-10); the previous revision of
  this file invented "file three upstream bugs" as a task and it was never asked for.
  The record exists so an audit hit on any of the three is not re-investigated as a
  fork problem, and so the `.symbol-exclusions` entries that exist because of them can
  be explained. **Do not re-propose filing.**
* **`models/qwen3_5_moe/qwen3_5_moe.py` is byte-identical to upstream on purpose.**
  The fork's `gate_proj` probe and upstream's `up_proj` probe were shown equivalent on
  every layout that can exist and exact mirror images on the two that cannot.
  `tests/test_qwen3_5_moe_sanitize.py` is fork-only and is now the sole carrier of that
  knowledge; `test_a_partial_expert_layout_raises` exists to stop the probe coming back.
* **`.fork-marker-allowlist` and `.body-divergence-exclusions` being empty is not a
  reason to delete them.** Both keep their headers and RESOLVED notes deliberately; the
  next merge that adds a fork hunk to a shared file will need an entry, exactly as
  `server/request_normalization.py` did.
* **`_rotating_post_gen_trim_safe` is intentionally unwired.** The mid-prefill snapshot
  supersedes it; wiring it would force full re-prefill on wrapped SWA rings.
* **`models/base.py`'s chunked `cache.quantized_attention`** — O(chunk) peak memory
  instead of O(context). The only reason `base.py` is not byte-identical.
* **`utils.py`'s remaining 12 missing upstream lines** are all the fork's
  `print`/`logging` → module-logger conversions (`2f5e01dd`), plus one comment inside
  the same converted block. Not a gap.
* **The two `check_fork_markers.py` case-4 coverages** (`dispatch.py`'s
  `_cache_fully_retained` / `_prefix_cache_trim_amount`, `generation.py`'s
  `_sample_top_p_one`). The script names them every run; they rest on
  `.symbol-exclusions` entries that now carry real reasons.
* **`.registry-exclusions`' 5 entries are all reviewed re-exports** the fork replaced
  on purpose, each verified at its import site rather than assumed. A sixth appearing
  means either a new deliberate replacement or a dropped re-export, and
  `tests/test_registry_check.py` pins the count so it cannot grow silently.
* **`find_untested_fork_code.py` is not a gate and should not become one.** An
  exclusions file would mean ~18 written reasons for things mostly fine, producing ~18
  unreviewed ones; and a hit is risk, not a correctness claim. Its docstring argues this
  at length so nobody promotes it.
* **`check_upstream_registries.py` compares presence, not values, deliberately.**
  `{"a": 1}` vs `{"a": 2}` passes. Values diverge legitimately across this fork; keys
  almost never do. Do not "improve" it into a value comparison — that is
  `check_body_divergence.py --file`'s job.
* **`check_body_divergence.py` does not gate on "every differing body is reviewed",
  and that is deliberate.** `check_fork_markers.py` already covers each diverging site,
  and a second ledger would have meant ~50 entries nobody had looked at — the exact
  "baseline: pre-existing divergence, unreviewed" anti-pattern `.symbol-exclusions`
