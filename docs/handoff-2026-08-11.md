### 2a. Promote the AST body-diff to `dev/check_body_divergence.py`

**The highest-value item, and the reason the other three are small.** `AGENTS.md`'s
"the fifth direction" documents a ~25-line comparison that answers the one question no
audit can: *is this file's divergence CONTENT, or only ALIGNMENT?* It is currently prose
and a copy-paste snippet, so it only runs when someone remembers. As a `dev/` script it
becomes a gate.

Its track record in one session, all from the snippet in `AGENTS.md`:

* `apc.py` — 74 of 76 definition bodies byte-identical; "554 missing lines / 36 sites"
  was four block moves. Converged to 2 missing lines.
* `turboquant.py` — 91 of 96 identical, which reduced the file to five functions and
  surfaced `#1433`'s dropped prefill gate that **three earlier report-based passes had
  missed**.
* `tests/test_generate.py` — 47 of 49 identical; residual was pure ordering, 5 sites → 0.
* `server/openai.py` — 27 of 31 identical, and it caught a byte-identical function
  sitting ~900 lines out of place inside a file that is otherwise a real rewrite.

**What it should report**, per diverged file: shared definition count, how many bodies
are byte-identical, `ours-only` / `up-only` names, whether module-level statements
match, and for each differing definition its line counts plus changed-line count. The
existing snippet already does all of this — the work is packaging, an exclusions file in
the house style (`path::symbol  # reason`), and a `--summary` that ranks files by
*content* divergence rather than line count.

**Two things to get right, both learned the hard way:**

- **Comments are not AST nodes.** A node-based reorder lands a relocated definition on
  the wrong side of a `# ===` banner. If the script suggests reorders, it must say this.
- It should be honest that `ours >= upstream` occurrence counts mean *rewrite* while
  `ours < upstream` is the only signal worth chasing — the cheaper identifier-count
  technique is strictly weaker and belongs downstream of this one.

Add tests to `mlx_vlm/tests/test_fork_marker_check.py`'s sibling pattern.
**`tests/test_fork_marker_check.py` is the only test of any `dev/` audit** and exists
because a bug that makes one of these checks *more permissive* fails nothing, still
prints OK, and silently stops reporting dropped content. A new gating script needs the
same treatment.
