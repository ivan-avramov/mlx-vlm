## Traps from this session — all cost real time

1. **`cd` persists in the shell between tool calls.** A `cd mlx_vlm/` for pytest
   left every later relative-path `git log`/`ls-tree` resolving against
   `mlx_vlm/mlx_vlm/`, which returns *empty output* rather than an error — so two
   files looked fork-only when they were not. Prefer absolute paths, or `git -C`.
2. **A rule calibrated on nothing is a rule that fails its own exemplar.** The
   fork-marker check was first written per-hunk; `models/cache.py`, the one file
   already following the convention, *failed*. If a new check fails the thing it
   was modelled on, the check is wrong, not the file.
3. **Order matters in an allowlist check.** Consulting the allowlist before
   computing coverage silently accepts entries for already-clean files, so the
   stale-entry warning can never fire for them. Compute first, suppress second.
4. **isort moves your marker.** A standalone comment inside a parenthesized
   `from x import (...)` block gets hoisted to the `import (` header line, so a
   marker can never sit adjacent to an added name there. Hence multi-line
   statements count as marker spans.
5. **"Taking upstream's version broke a test" proves nothing about which side is
   right.** It proves the two sides are internally consistent and you are holding
   half of each. Test *all* of a commit's files together before concluding.
   `gemma4_assistant/masks.py` was mis-documented as a deliberate divergence for
   exactly this reason.
6. **Upstream may already have the structure you are about to hand-merge.** Its
   `app.py` had the delegating wrappers the gen-args union needed, including the
   indirection that looked like fork work. Read upstream's target shape first.
7. **`from mlx_vlm.server import app` returns the FastAPI instance, not the
   module** — `server/__init__.py` mirrors `app.py`'s namespace and `app` is one of
   its names. Use `importlib.import_module`. Same shape as
   `import mlx_vlm.convert` returning the re-exported function.
8. **`cp` is aliased to `cp -i` here.** A restore-from-backup silently did nothing
   and left a test edit in place. Use `command cp -f`, and re-check `git status`.
9. **A `-U0` hunk count is not a work estimate.** `apc.py` reports 361 hunks inside
   4 default-context regions. Count *sites*.
10. **Never read a count off a truncated pipe.** `find_dropped_hunks.py | tail -60`
    was counted as "18 commits"; the real number, on the report's own header line,
    was 34. It reached a commit message before being noticed. Every audit here
    prints its own totals — use those.
