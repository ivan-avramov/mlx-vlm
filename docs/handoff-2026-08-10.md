`test_server.py` is **partly gated on 2a and 2b** — much of its missing content is

`a30180a6`, `ea2edd68` and `e029e2b3` all landed last pass, so only upstream's tests
for them are absent, and `c503fa7b`'s 51 lines there are *superseded*, not missing.

**The method is four for four** (`test_utils.py`, `test_trainer_utils.py`,
`test_batch_quantized_cache.py`, `test_speculative.py`). The order of the steps is
what makes it safe:

1. AST-compare definition names both ways. **`only_ours` empty does NOT mean
   checkout-safe** — `test_utils.py` had zero fork-only definitions and still had
   real fork content in *bodies*.
2. Diff the *bodies* of shared definitions. Anything ours-only is either a fork
   adaptation (keep it, mark `# Fork:`) or a weakened assertion (take upstream's).
   These look identical in a diff; `memory.md`'s change log is what distinguishes
   them — `test_speculative.py`'s one-ULP bound is a legitimate relaxation recorded
   in `4b15cc5`.
3. Take upstream's file as the base so future merges apply cleanly, then re-append
   fork-only definitions below a `# Fork additions below this line` banner.
4. Union the import block, marking fork-only imports (`# Fork:` inline — a
   standalone comment gets hoisted by isort).
5. Re-run `check_upstream_symbols.py` and `check_fork_markers.py` and prune whatever
   stops being excused, **in the same commit**.

## 3. The pattern that produced most of last pass's real bugs

Worth internalising before you start, because it is still the most likely thing you
will find: **"the symbol exists and nothing calls it."**

Missing *wiring*, not missing code. The helper is present, importable, and usually
unit-tested — so the suite is green and the audits are quiet. Five instances last
pass, three user-visible: embedding models silently ignored their
`1_Pooling/config.json`; the APC cache key omitted audio/video/embeddings/masks so
requests differing only in media **shared a prefix cache**; three sampler modes were
accepted by the API and discarded.

`dev/check_dead_helpers.py` now gates that shape (~10s, currently 0 exclusions).
When something looks unused, ask whether **upstream** calls it before concluding it
is fork scaffolding.

## 7. Traps — every one of these cost real time

1. **`cd` persists between tool calls, and a wrong relative path returns *empty
   output*, not an error.** Bit **three times** last session: `git log` / `ls-tree` /
   `git diff` silently resolving against `mlx_vlm/mlx_vlm/`, which twice made a file
   look fork-only and once looked like "byte-identical to upstream". **Use
   `git -C /Users/ia87221/ws/mlx-vlm` unconditionally.**
2. **`mlx_vlm.generate` is the re-exported *function*, not the module.** So
   `import mlx_vlm.generate.ar` fails with a confusing `ImportError`, and
   `from mlx_vlm.server import app` hands back the FastAPI instance rather than the
   module. Use `importlib.import_module`.
3. **`cp` is aliased to `cp -i` here.** A restore-from-backup silently did nothing
   and left a neutering edit in the tree. Use `command cp -f`, then check
   `git status`.
4. **Never read a count off a truncated pipe.** `find_dropped_hunks.py | tail -60`
   was counted as "18 commits"; the real number was 34, and the wrong figure reached
   a commit message. Every audit prints its own totals — use those.
5. **"Unreferenced" is not "dead".** autoflake's removal of
   `DEFAULT_DIFFUSION_CONFIDENCE_THRESHOLD` was correct on its own terms and wrong in
   effect: the name was unused *because* `f044f36a` had been dropped, so tidying it
   erased the last evidence of a missing hunk. Before accepting an autoflake removal
   in a diverged file, check whether **upstream** references the name.
6. **A "fully converged" claim about a file says nothing about the feature.**
   `0f359e5` recorded "`apc.py` fully converged with upstream" while all three of its
   new helpers had no call sites.
7. **"Taking upstream's version broke a test" proves nothing about which side is
   right.** It proves the two sides are internally consistent and you are holding
   half of each. Test *all* of a commit's files together — this is how
   `gemma4_assistant/masks.py` got mis-documented as a deliberate divergence.
8. **A test can be edited to tolerate its own bug** — and a legitimate numerical
   relaxation looks identical in the diff. AST-diff *bodies*, and check the change
   log for a recorded reason.
9. **A rule calibrated on nothing fails its own exemplar.** The fork-marker check was
   first written per-hunk, and `models/cache.py` — the one file already following the
   convention — failed it. If a new check fails the thing it was modelled on, the
   check is wrong.
10. **Validate a new detector fires before trusting a clean run**, in both
    directions: break the thing it should catch and see it fail, then restore and see
    it pass.
